## Commit
Repository: `/home/mstouffer/repos/handex-proj/KeySequences`

## What Broke It
The caller wrapper was added in `/home/mstouffer/repos/handex-proj/KeySequences/Makefile`:
```makefile
publish-board: ## Publish-HandChords from flashed handex.c (matches the programmed module)
	python3 publishHandChords.py --source firmware
```

When `publishHandChords.py --source firmware` runs, it parses the firmware file (`handex.c`) using regex:
```python
CASE_RE = re.compile(
    r"case 0x([0-9A-Fa-f]+):\s+result = (0x[0-9A-Fa-f]+);\s+//.*?=>\s*(.*?);",
    re.S,
)
```

In `handex.c` (line 118 generated by `makeKeys.js` / `maps.js`):
```c
case 0x9:       result = 0x33; // pmf =>                      ; and :;
```

Because `CASE_RE` terminated with non-greedy `\s*(.*?);`:
It stopped on the first semicolon `;` inside `; and :;`.
The regex captured:
- `chord_hex = "9"`
- `value = "0x33"`
- `report = ""` (empty string!)

`publishHandChords.py` then wrote `handterm/src/allChords.ts` directly:
- At index 46, `"key"` was written as `""`
- Semicolon `;` was lost
- Shifted colon `:` was dropped completely because `right` was `None`.

## The Fix in KeySequences
Update `CASE_RE` in `/home/mstouffer/repos/handex-proj/KeySequences/publishHandChords.py` so that it matches to the end of the comment line rather than stopping at the first semicolon:
```python
CASE_RE = re.compile(
    r"case 0x([0-9A-Fa-f]+):\s+result = (0x[0-9A-Fa-f]+);\s+//.*?=>\s*(.*?);\s*$",
    re.M,
)
```
or split on `//.*?=>\s*` and strip the trailing `;` or newline.
